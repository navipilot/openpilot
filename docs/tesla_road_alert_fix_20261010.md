# Tesla 上路 UI 报警修复报告

## 结论与范围

针对本次 Model 3 上路记录中的反复转向饱和、转向暂时不可用报警，
修复了停用转向报文与 Panda 校验不一致的问题，并修正最终请求反馈和
饱和判定。另修复 Tesla 纵向报文意外重新授予控制权限的问题。

这不是隐藏报警的补丁。真实 EPS 故障、驾驶员监控、接管提示和退出时的
CAN/控制权限异常仍保留原有处理。模型、转向增益、角度/速率上限、主动
协同转向算法、纵向控制算法、AEB 和原车转发策略没有改动。

桌面回归、真实记录输入回放与 F4/H7 固件构建完成；尚未刷写车辆，也没有
修复后的实车复测。因此不能宣称已经消除了实车报警。

## 证据与根因

分析覆盖本地提供的八段完整 rlog，使用完整 cereal schema 解码，并区分
主机 `sendcan`、Panda 接受回执和拒绝回执。

原记录有 6,261 个被拒绝的转向回执，全部是停用转向请求。启用转向回执
没有同类拒绝。多次 EPS 临时故障出现在最后一个成功启用请求约
130–150 ms 后，期间停用请求持续被拒绝。

原协同控制器在停用时仍发送：

```text
测量转角 + 转角速度 / 8
```

Panda 要求停用请求接近最近的 EPS 测量角，并受绝对角度上限约束。快速
转动方向盘时，相位超前角不符合这个条件，造成停用报文被拒绝。
DBC 的故障码 4 是一般临时故障，不是明确的超时故障码；上述时序支持
报文中断是重要原因，但不构成厂家级故障因果证明。

另外，主机输出反馈返回协同调整前的角度，不能反映最终请求；
角度控制器又忽略了调用方提供的输出受限标志，可能在恢复限速过程中
积累饱和报警。

纵向安全检查存在独立缺陷：共享函数把非零原始加速度编码当成恢复权限
的理由。Tesla 的零加速度编码其实是 375，正常零请求也会走错误的授予
权限路径。该行为不能用于维持接管后的控制。

## 代码修复

| 文件 | 修复 |
| --- | --- |
| `opendbc_repo/opendbc/car/tesla/coop_steering.py` | 停用 CAN 请求使用 EPS 测量角，限制到 ±360°；内部相位超前、恢复限速和 override 重置历史保持原算法。 |
| `opendbc_repo/opendbc/car/tesla/carcontroller.py` | 独立保存最终协同请求角，CAN 和输出反馈使用同一个值；非发送周期保留最后请求，不覆盖上游限速历史。 |
| `openpilot/selfdrive/controls/lib/latcontrol_angle.py` | 将调用方的输出受限标志传入现有饱和计数器；持续、未受限的跟踪误差仍可报警，阈值不变。 |
| `opendbc_repo/opendbc/safety/safety/safety_tesla.h` | Tesla 专用范围和权限校验不再调用会修改权限的共享函数；无纵向权限时只能发送零加速度上下界。保留刹车/油门/巡航接管、倒车防护、AEB 和白名单。 |

输出反馈代表主机最后请求的转角，不代表物理方向盘角，也不是 Panda 的
实际发送确认。Tesla CAN 的转角符号转换和量化规则保持不变。

共享纵向函数在其他车型上的既有行为未在本次修改中扩大处理。

## 验证结果

### 生产控制器同输入比较

将修复前后生产控制器分别输入记录中的公开 carState/carControl，并从
原始 EPS 数据恢复强驾驶员 override 条件，共运行 47,328 次更新。
本比较不重建独立的自动调速滚轮状态机，且将 stock cancellation 的私有
状态固定为中性，因此不是整套 card 的逐字节录制重现。

| 项目 | 结果 |
| --- | --- |
| 启用转向报文 | 13,360 帧修复前后逐字节相同 |
| 停用转向输出 | 10,304 帧全部符合测量角及 ±360° 限幅 |
| 比较范围内的非转向报文 | 16,565 帧逐字节相同 |
| 内部历史 | 上游限速角和协同恢复限速状态逐更新相同 |
| 输出反馈 | 与最终请求一致；非发送周期保持最后请求 |

### 原始 RX / 主机 TX 安全回放

在原调查使用的启动后、退出前窗口，使用真实编译的旧/新 C 安全钩子，
按记录顺序重放 RX 与主机 TX。停用候选经实际生产协同函数和 Tesla CAN
打包函数生成，使用当前 RX 的 EPS 测量，未放宽 Panda 转角校验。

| 报文 | 修复前 | 修复后 |
| --- | --- | --- |
| 停用转向 10,039 帧 | 3,846 接受 / 6,193 拒绝 | 10,039 接受 / 0 拒绝 |
| 启用转向 13,355 帧 | 全部接受 | 全部接受 |
| 转向许可 4,679 帧 | 全部接受 | 全部接受 |
| 纵向请求 11,697 帧 | 全部接受 | 11,696 接受 / 1 拒绝 |

新增的一帧纵向拒绝发生在踩刹车、权限已撤回后：请求上下界原始编码为
363/375，即约 -0.48/0 m/s²，而非完全零请求。修复后正确阻断该残留请求，
不会通过 TX 重新打开权限。

记录批次顺序不是 MCU 的实际到达顺序，因此 6,193 是上述回放窗口的拒绝
数，不应替代全记录的 6,261 个真实拒绝回执。同输入回放也不能证明车辆
对修复后的报文会如何响应。

### 回归与固件

新增回归覆盖停用测量角、双向大角度限幅、恢复状态、协同/普通路径、
强 override、CAN 符号与量化、非发送周期反馈、受限/未受限饱和判定，
以及 Tesla 加速度双边范围、零请求不得授予权限、刹车/油门/巡航接管、
原车 AEB 和固件源身份变化。

集中回归结果：156 项通过、128 个子用例通过；35 项按原测试规则跳过，
14 项因下述既有兼容问题排除。缺少可选 pytest 插件产生三条配置警告。
执行命令：

```bash
.venv/bin/python -m pytest -q -o addopts='' \
  --confcutdir=.analysis/scratch/2026-10-10-road-fix \
  opendbc_repo/opendbc/car/tesla/tests \
  openpilot/selfdrive/controls/tests/test_angle_saturation.py \
  openpilot/system/tests/test_panda_firmware_version.py \
  opendbc_repo/opendbc/safety/tests/test_tesla.py \
  -k 'not fwd_hook and not stock_aeb_passthrough and not angle_cmd_when_disabled and not tx_hook_on_wrong_safety_mode'
```

安全测试链接真实 C 安全钩子；本地独立构建真实 Params 绑定，未用假 Params
替换生产行为。完整旧安全套件存在以下已识别限制，未声称全套通过：

- 旧转发测试按 `(bus, address)` 调用已改为报文指针的 C 接口，会导致测试
  进程崩溃，因此排除；本次未修改转发代码。
- 三个旧 disabled-angle 测试与本仓库共享 AlwaysLateral 权限行为冲突；
  同样测试旧 HEAD 的 C 库也失败。本次未修改共享权限策略。
- 跨所有车型的 wrong-safety-mode 测试因缺少 `parameterized` 依赖排除；
  其范围超出本次 Tesla 修复。
- `stock_aeb_passthrough` 因使用同一个旧转发接口排除，另加独立 RX/TX
  回归验证原车 AEB 仍能阻止主机纵向发送。

`scons -C panda -Q --minimal -j2` 完成 F4/H7 普通与 Tesla wake 变体构建，
开启编译器错误检查。固件身份回归确认 Tesla 安全头文件变化会触发更新。
修改文件的 Ruff 检查未发现新增问题；角度控制文件已有的未使用 numpy
导入和函数定义尾随空格，在旧 HEAD 中也存在，未做无关清理。
本地原始证据、脚本、基线对照和详细结果保留于忽略的 `.analysis/archive/`
目录，不纳入提交。

## 上车验证要求

此修改包含 Panda 安全代码，必须让设备正常重新构建并刷入匹配固件；
仅更新主机 Python 代码不能获得纵向权限修复。不得跳过固件版本检查。

实车复测应先在安全条件下验证停用、驾驶员接管、重新接入和刹车退出，
确认真实 Panda 接受/拒绝回执、EPS 状态及对应 UI 报警。记录中的 DM 提示
没有足够证据判定误报，未改动 DM 检测或屏蔽提示。若复测仍出现 EPS
临时故障，应继续调查原始状态码及 CAN 时序，而不是关闭故障报警。
